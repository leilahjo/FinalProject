# Project Status Update Instructions

**Points:** 50

**Objective:**
The goal of this check-in is to ensure you are making steady progress on your project.

**Instructions:**
Please submit a brief update on your project's current status. You do not need to have a fully playable game yet, but there should be evidence of active development.

In your submission, please provide:
1. **GitHub Link:** A link to your forked repository showing your recent commits.
2. **Engine Progress:** A short bulleted list of the engine features from your proposal's complexity matrix that you have started or completed.
3. **Game Progress:** A short bulleted list of the gameplay features you have been working on.
4. **Blockers:** Are you stuck on anything? Let us know if you need help with specific C++ bugs, Raylib issues, or architectural decisions. If you have no blockers, just state "None."
5. **Profiling (new!):** Perform a profiling experiment on some section of your game or engine. Attempt to improve the code and measure the performance. Include the relevant code (before and after), why you thought your change might improve the performance, and the measurements (before and after). You are not required to demonstrate an actual improvement.
6. **LLM Usage (If Applicable):** As a reminder, if you used an LLM as an advisor for debugging or planning, you must include a link to the Google Doc containing your entire conversation log. 

**Grading:**
The progress update is a low-stakes assignment designed to keep you on track. The profiling is a little bit more involved.
